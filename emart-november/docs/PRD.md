# 이마트 11월 프로모션 웹페이지 PRD

제품 요구사항 문서 · v0.2 · 2026년 10월 15일

## 1 제품 개요와 목표

**권장안은 이마트의 브랜드와 매장 쇼핑 흐름을 반영한 모바일 우선 행사 페이지다.** 고객이 점포를 선택하고, 행사 일정과 구매 조건을 이해한 뒤 매장에서 이용하도록 설계한다. 캠페인 이름은 **이마트 고래잇! 알뜰한 11월 장보기**로 사용한다. 공식 이마트앱의 전단·혜택·점포 안내 방식을 참고하되, 첫 화면의 행동은 점포 선택과 혜택 확인에 집중한다.

| 항목 | 내용 | 결정 상태 |
| --- | --- | --- |
| 행사 기간 | 2026년 11월 2일 월요일부터 11월 29일 일요일까지 총 28일 | 제공 자료 |
| 대상 점포 | 센트럴점 · 파크점 · 리버점 | 제공 자료 |
| 행사 구성 | 식사 콤보 · 주말 즉시 할인 · 연계 구매 · 리버점 퇴근길 할인 | 제공 자료 |
| 페이지 형태 | 한국어 반응형 랜딩 페이지 1개 | 설계 제안 |
| 주요 행동 | 점포 선택 → 해당 혜택 확인 → 구매 조건 확인 | 설계 제안 |

### 고객이 해결할 일

- 점심이나 저녁을 준비하는 고객은 간편식과 음료를 함께 살 때의 할인 조건을 확인한다.
- 주말 장보기 고객은 35,000원 구매 조건과 2,000원 즉시 할인 기준을 확인한다.
- 신선식품 구매 고객은 추가로 할인받을 수 있는 가공식품과 수량 제한을 확인한다.
- 리버점 방문 고객은 퇴근길 할인 시간과 조기 종료 가능성을 확인한다.

### 해결할 문제

포스터의 네 가지 행사는 적용 요일, 시간, 금액, 점포가 서로 다르다. 큰 할인 숫자만 먼저 읽으면 모든 상품이나 모든 점포에 적용되는 것으로 오해할 수 있다. 웹에서는 각 할인 숫자 가까이에 핵심 조건을 배치하고, 점포와 일정을 함께 보여준다.

### 첫 구현 범위

공식 로고, 행사 소개, 점포 선택, 일정 안내, 네 가지 혜택, 매장 이용 방법, 유의사항을 구현한다. 영업시간과 휴점일은 확인된 점포 정보로 안내한다. 점포 정보가 미확정이면 그 상태를 표시하고 공식 점포찾기로 연결한다.

쿠폰 발급, 로그인, 장바구니, 온라인 결제, 실시간 재고, 영수증 확인, 관리자 화면은 후속 범위로 둔다. 현재 자료에는 이 기능을 운영할 정보가 없다.

## 2 실제 이마트 서비스와 적용 방향

공식 CI, 이마트앱 공개 안내, 현재 행사 페이지와 점포 상세를 기준으로 아래 방식을 반영한다. **실제 서비스에서 확인한 사실과 이번 페이지의 설계 제안을 구분한다.** 다른 행사에 붙은 카드·포인트 조건을 이번 행사 조건으로 추가하지 않는다.

| 공식 서비스에서 확인한 내용 | 이번 페이지에 반영할 설계 | 근거 |
| --- | --- | --- |
| 소문자 emart와 부드러운 곡선을 사용하는 CI | 공식 로고 원본을 헤더에 사용하고 비율과 색 유지 | W1 |
| 앱 메뉴에서 전단·이벤트·카드행사·쿠폰을 구분 | 행사 정보와 적용 조건을 분리하고 목적이 분명한 버튼 사용 | W2 |
| 단골점포의 행사·휴점일 안내 제공 | 방문 점포를 먼저 고르고 영업 정보와 일정 함께 확인 | W3 |
| 행사 상세에서 기간·대상 상품·사용 조건·점내 안내를 제공 | 카드 기본 화면에 핵심 조건, 펼침 영역에 추가 제한 표시 | W4 |
| 점포 상세에서 영업시간·휴점일·주소·층별안내 제공 | 검증된 점포 정보를 연결하고 매장 이용 순서를 안내 | W5 |
| 앱에서 상품·재고 확인 및 포인트·쿠폰·결제 기능 제공 | 공식 서비스로 연결하되 실제 연동 전에는 해당 기능을 재현하지 않음 | W6 |

### 매장 이용과 연결하는 방식

방문 전에는 점포와 전단·행사를 확인하고, 매장에서는 행사 표시 상품과 구매 조건을 확인하는 흐름으로 연결한다. 공식 고래잇 행사에서도 품목별 카드·포인트 조건과 점내 고지 확인을 안내한다. 따라서 ‘할인 숫자 → 대상 상품 → 적용 조건 → 매장 확인’ 순서로 정보를 제공한다. 이 순서는 실제 안내를 참고한 설계 제안이다. [W7]

쿠폰은 실제 이마트 서비스의 한 기능이지만, 첨부 행사에 쿠폰 다운로드가 필요하다고 명시되어 있지는 않다. 이 페이지에는 ‘쿠폰 받기’를 주요 버튼으로 넣지 않는다. 할인 자격과 자동 적용 여부가 확정되면 이용 안내를 갱신한다.

## 3 행사 조건과 표시 규칙

### B01 식사 콤보

**15% 할인.** 간편식 1개와 음료 또는 유제품 1개를 같은 영수증으로 동시에 구매하는 조건이다. 센트럴점, 파크점, 리버점을 대상으로 한다. 시간은 11:30~13:30 및 17:30~19:30이다.

요일은 종합 포스터의 **월~목**을 구현 기준안으로 둔다. 개별 포스터의 ‘평일’ 표기와 차이가 있어 확정이 필요하다. 타 쿠폰 및 기존 수량 할인과 중복 적용할 수 없다는 조건을 상세 영역에 표시한다. 할인 대상 금액의 구체적인 범위는 확인이 필요하다.

### B02 주말 혜택

**35,000원 이상 구매 시 2,000원 즉시 할인.** 금~일에 세 점포에서 진행한다. 구매 금액은 **다른 상품 할인을 적용한 후, 이번 2,000원 즉시 할인을 적용하기 전 금액**을 기준으로 한다. 단일 영수증 기준이며 영수증 합산은 불가하다.

설명 예시는 “다른 상품 할인 반영 후 대상 구매 금액이 35,000원이면, 2,000원 즉시 할인 후 33,000원”으로 제시할 수 있다. 제외 품목과 추가 자격 조건은 확인 후 반영한다.

### B03 매일 함께 사면

**행사 신선식품 10,000원 이상 구매 시 지정 가공식품 15% 할인.** 세 점포에서 매일 진행한다. 지정 상품군은 즉석밥, 참치, 멸치이며 최대 2개다. **15% 할인 대상은 지정 가공식품**이라는 점을 카드 전면에 표시한다.

정확한 대상 상품 목록, 10,000원 산정 시점, 최대 2개의 합산 방식 및 동일 영수증 조건은 확인이 필요하다. 자료에 없는 할인 금액이나 상품 가격은 계산하지 않는다.

### B04 리버점 퇴근길 할인

**리버점 단독 20% 할인.** 매일 17:00~20:00에 당일 행사 신선식품과 간편식을 대상으로 한다. 준비 수량 소진 시 조기 종료된다. 카드와 상세 영역 모두에 ‘리버점 단독’ 및 ‘준비 수량 소진 시 조기 종료’를 표시한다.

### 공통으로 전달할 조건

- 행사 표시 상품에 한해 적용한다. 모든 상품에 할인이 적용된다는 표현은 사용하지 않는다.
- 자세한 대상 상품과 적용 조건은 매장 안내를 확인하도록 한다.
- 콤보의 중복 불가 조건은 B01에 연결한다. 다른 세 혜택에도 동일하게 적용된다고 확대하지 않는다.
- 행사 간 중복 적용 여부가 확정되기 전에는 합산 할인율이나 최대 절약 금액을 안내하지 않는다.

## 4 화면 구성과 고객 흐름

**첫 화면에서 행사 이름과 기간을 이해하고, 점포 선택 후 바로 혜택을 확인하도록 구성한다.** 할인 조건은 별도의 팝업을 열지 않아도 기본 화면에서 읽을 수 있어야 한다.

| 순서 | 화면 영역 | 반드시 보일 내용 | 주요 행동 |
| --- | --- | --- | --- |
| 0 | 간결한 상단 헤더 | 공식 emart 로고, 행사 안내, 현재 선택 점포 | 선택 점포 변경 |
| 1 | 행사 첫 화면 | 캠페인 이름, 행사 기간, 고래 이미지, 대상 3개 점포 | 내 점포 혜택 보기 |
| 2 | 점포 선택 | 센트럴점 · 파크점 · 리버점, 선택 상태 | 점포 선택 또는 변경 |
| 3 | 선택 점포 안내 | 점포명, 영업·휴점 확인 상태, 한국 기준 행사 일정 | 공식 점포 정보 확인 |
| 4 | 혜택 카드 | 할인 수치, 대상, 요일, 시간, 금액·수량 조건 | 자세한 조건 펼치기 |
| 5 | 매장 이용 방법 | 행사 표시 상품 확인, 구매 조건 확인, 매장 적용 안내 | 이용 순서 확인 |
| 6 | 유의사항 | 공통 조건, 혜택별 제한, 행사 기간 | 전체 조건 확인 |

### 점포 선택 전후 동작

처음에는 점포를 임의로 선택하지 않는다. 세 점포를 큰 선택 버튼으로 한 화면에 보여주고, 로그인이나 위치 권한 없이 선택하게 한다. 선택을 건너뛰어도 공통 혜택 3개와 리버점 전용 카드를 읽을 수 있다. ‘점포를 선택하면 해당 점포의 혜택을 확인할 수 있어요’라고 안내한다.

센트럴점이나 파크점을 선택하면 공통 혜택 3개를 표시한다. 리버점을 선택하면 공통 혜택과 전용 혜택까지 총 4개를 표시한다. 점포 변경 시 카드, 요약 문구, 하단 버튼의 점포명을 즉시 함께 갱신한다. 카드 순서는 B01부터 B04까지 고정한다.

### 대표 이용 상황

11월 2일 월요일 12시에 센트럴점을 선택한 고객은 식사 콤보 시간대와 연계 구매 행사를 확인한다. 11월 6일 금요일 18시에 리버점을 선택한 고객은 주말 혜택과 퇴근길 할인 시간대를 함께 확인한다. 두 경우 모두 상품 조건 충족이나 중복 할인을 보장하는 문구는 표시하지 않는다.

### 버튼과 이동

첫 화면의 ‘내 점포 혜택 보기’는 점포 선택 영역으로 이동한다. 선택 후 모바일 하단 버튼은 ‘센트럴점 혜택 보기’처럼 실제 선택명을 표시하고 혜택 영역으로 이동한다. 시작 전에는 ‘행사 혜택 미리 보기’로 안내한다. ‘할인 조건 보기’는 카드 내부를 펼친다. 핵심 할인 조건은 펼치기 전에도 보인다.

보조 링크 ‘이마트 공식 점포찾기’는 공식 서비스로 연결한다. 점포별 매핑이 확정되면 해당 점포 상세로 연결한다. 혜택은 4개이므로 별도의 검색창이나 복잡한 카테고리 메뉴는 두지 않는다. 자동 팝업, 자동 넘김 배너, 앱 설치 요구로 혜택 확인을 막지 않는다.

## 5 날짜와 시간에 따른 화면 동작

모든 일정은 **한국 표준시 Asia/Seoul**로 판정한다. 기기의 현지 시간대가 달라도 한국 기준 요일과 시간을 사용한다. 시간 판정은 행사 일정을 알려주는 기능이며, 매장 영업 여부나 재고를 확인하는 기능으로 사용하지 않는다.

| B01 다른 시간 | 기간 내 월~목, 운영 시간 외 | 오늘 11:30~13:30 · 17:30~19:30 |

| B03 행사 기간 | 기간 내 모든 요일 | 행사 신선식품과 함께 확인하세요 |
| B04 해당 시간 | 리버점 선택, 기간 내 매일 17:00~20:00 | 퇴근길 행사 시간대예요 · 소진 시 종료 |

### 경계와 갱신 규칙

행사 시작 전·종료 후 안내를 먼저 판정한다. 기간 중에는 확인된 휴점일과 영업시간을 행사 시간 강조보다 우선 적용한다. 휴점일이면 ‘현재 행사 시간대’ 강조를 해제한다. 영업 정보가 없으면 행사 일정만 안내하고 ‘영업중’이나 ‘지금 구매 가능’을 표시하지 않는다.

시간대는 시작 시각을 포함하고 종료 시각부터 다음 상태로 전환하는 구현안을 사용한다. 예를 들어 B01은 11:30부터 표시하고 13:30에 해제한다. B04는 17:00부터 20:00 직전까지 해당 시간으로 판정한다. 실제 할인 마감 시각의 운영 기준은 확정 항목에 포함한다.

페이지를 열 때, 점포를 바꿀 때, 분이 바뀔 때와 화면에 다시 돌아올 때 안내 상태를 갱신한다. 날짜 계산과 화면 표시에 동일한 시간대 설정을 사용한다. 점포 선택은 현재 페이지 이용 중 유지하며 새로 열면 미선택으로 시작한다.

### 비해당 일정과 종료 화면

오늘 해당하지 않는 혜택도 전체 일정 확인을 위해 카드에 남긴다. ‘월~목 운영’이나 ‘17:00부터’처럼 다음 이용 조건을 보여준다. 지난 시간의 혜택이 비활성화된 것처럼만 보이지 않게 한다. 행사 종료 후에는 모든 현재 일정 강조를 해제하고 종료 안내를 가장 위에 표시한다.

품절 여부는 데이터가 없어 자동 판정하지 않는다. ‘실시간 할인 가능’, ‘재고 있음’, ‘구매 확정’처럼 보장하는 표현은 사용하지 않는다. 개발 검토용 날짜·시간 조작 기능을 넣는 경우에는 별도 체험 모드로 표시하고 일반 화면과 구분한다.

### 로고 사용

공식 emart 원본을 사용하고 비율·형태·색을 유지한다. 일반 글꼴이나 이미지 생성으로 로고를 다시 만들지 않는다. CI 페이지의 격자가 포함된 설명용 이미지는 헤더에 넣지 않는다. [공식 웹 로고 SVG](https://eappfront.emart.com/assets/icon-logo-emart.svg?v=f787ff23)를 원본 후보로 지정한다. 헤더 너비 80~96px는 화면 설계 제안이다. [W1]

- 모바일은 360px 너비부터 가로 스크롤 없이 구성한다. 혜택 카드는 세로 한 열로 배치한다.

### 이미지와 접근성

포스터를 통째로 붙여 본문을 대신하지 않는다. 기간, 할인, 제한 조건은 선택·검색 가능한 웹 텍스트로 구현한다. 로고, 고래, 상품 이미지는 별도 자산이 준비되면 사용하며 원본 비율을 유지한다. 상품 이미지는 예시로 표시해 실제 행사 품목으로 오해하지 않게 한다.

일반 글자 대비 4.5:1 이상, 버튼 터치 영역 48px 이상을 구현 목표로 둔다. 큰 할인 숫자도 배경과의 대비를 확인한다. 점포 선택과 상세 펼침은 키보드로 조작할 수 있어야 한다. 선택 상태와 펼침 상태를 보조기기에도 전달한다. 의미 있는 이미지에는 대체 텍스트를 제공하고 장식 이미지는 읽기 흐름에서 제외한다.

### 매장에서 이용하는 순서

고객에게는 ① 행사 표시 상품 찾기 ② 조합·금액·시간 조건 확인하기 ③ 계산 전 적용 조건 확인하기 순서로 안내한다. 포인트 제시나 별도 쿠폰이 필요한 경우는 확정된 정책에 따라 추가한다. ‘모든 할인이 자동 적용된다’는 문구는 사용하지 않는다.

점포별 매대 위치와 층 정보가 확정되면 ‘어디서 찾나요’에 연결한다. 그 전에는 실제 매장 배치도를 만들거나 특정 층에 있다고 안내하지 않는다. 매장 직원 확인용으로도 동일한 혜택명과 조건을 사용한다.

### 쉽게 확인할 질문

‘어느 점포에서 받을 수 있나요’, ‘신선식품도 15% 할인되나요’, ‘다른 할인과 함께 받을 수 있나요’, ‘퇴근길 행사 상품이 품절되면 어떻게 되나요’를 짧은 문답으로 제공한다. 미확정 답변은 ‘매장 안내 확인’으로 표시하고 임의의 정책을 추가하지 않는다. B01 같은 내부 관리 ID는 고객 화면에 노출하지 않는다.

검토자 5명 중 4명 이상이 10초 안에 행사 기간과 대상 점포를 찾는 것을 목표로 한다. 별도 설명 없이 콤보 시간, 주말 금액 기준, 리버점 제한도 답할 수 있는지 확인한다. 초기 검수 목표이며 실제 성과가 아니다.

모바일 주요 콘텐츠 표시 2.5초 이내, 초기 자산 2MB 이하를 성능 목표로 둔다. 텍스트와 버튼을 먼저 사용할 수 있어야 하며, 이미지 로딩 중 화면 밀림과 하단 버튼의 본문 가림을 검수한다.

### 측정할 행동

분석 도구 연결 시 page_view, store_select, benefit_detail_open, notice_open, official_store_link_click을 기록한다. 점포·혜택 ID와 버튼 위치만 사용한다. 상세 확인은 실제 펼침 클릭 시 기록한다.

점포 선택률은 방문 세션 중 선택 세션 비율이며, 상세 확인률은 조건을 펼친 세션 비율이다. 기준값 확보 후 목표를 정한다. 웹 행동을 매장 방문·매출 성과로 환산하지 않는다.

## 10 확정할 사항과 다음 작업

### 행사 조건 확정 항목

| 항목 | 현재 확인한 내용 | 확정할 내용 |
| --- | --- | --- |
| 콤보 요일 | 개별 이미지 평일 · 종합 이미지 월~목 | 금요일 포함 여부 |
| 콤보 할인 기준 | 간편식 1개와 음료 또는 유제품 1개 | 15%가 적용되는 금액 범위와 대상 품목 |
| 주말 할인 | 35,000원 이상 · 2,000원 · 단일 영수증 | 제외 품목, 횟수 제한, 추가 자격 조건 |
| 연계 구매 | 행사 신선식품 10,000원 · 가공식품 15% · 최대 2개 | 금액 산정 시점, 상품 목록, 수량 합산, 영수증 조건 |
| 행사 간 중복 | B01 타 쿠폰·수량 할인 중복 불가 | 네 혜택 상호 중복 및 적용 순서 |
| 영업 및 마감 | 시간 제한 행사 두 종류 명시 | 실제 점포 ID·휴점일·영업시간·할인 종료 경계 |

행사 조건이 미확정인 동안 화면 검토본에는 ‘조건 확인 중’을 명확히 표시한다. 실제 고객에게 안내하는 버전에는 확정된 조건만 반영한다. 이 문서의 기본 설정은 월~목 콤보이며, 금요일 15% 콤보를 추가로 약속하지 않는다.

### 제작에 필요한 자산과 운영 정보

공식 로고 자산을 준비하고 고래 캐릭터 원본, 상품 이미지, 행사 상품 목록을 확정한다. 글씨는 웹 텍스트로 다시 입력한다. 피코크·노브랜드 등 상품 브랜드 로고는 실제 대상 상품이 확정된 경우에 사용한다. 점포 주소, 공식 URL, 영업·휴점 정보를 함께 확정한다.

페이지 용도는 과제·시연용인지 실제 고객 공개용인지 결정한다. 실제 공개용이면 안내 문구와 문의 채널을 확정하고, 필요한 경우 분석 도구와 운영 중 수정 담당자를 정한다. 문서에는 센트럴점·파크점·리버점을 제공 자료의 점포명으로 사용한다.

### 진행 순서

1. 콤보 요일과 행사 조건을 확정하고, P0 범위를 고정한다.
2. 모바일 첫 화면, 점포 선택, 혜택 카드의 화면 초안을 만든다.
3. 공통 행사 데이터와 한국 시간 판정부터 구현한다.
4. 네 혜택, 상세 펼침, 이용 방법과 종료 화면을 연결한다.
5. T01~T14와 사용성 목표를 검토하고 문구·화면을 조정한다.
